# TitleExtractor 插件优化规划

## 项目概述

TitleExtractor 是一个 Obsidian 插件，主要功能是根据正则表达式提取文件名中的内容来替换文件的显示名称，优化双链接缓存并提升显示性能。当前项目存在架构复杂、代码冗余等技术债务问题，需要进行全面优化。

## 优化目标

1. 简化架构，减少服务组件数量
2. 重构缓存系统，提高性能
3. 增加测试覆盖率
4. 改进错误处理机制
5. 优化代码质量
6. 简化用户配置

## 第一阶段：架构重构（4周）

### 1.1 服务层重组（2周）

- **将过度分割的服务合并**
  - 合并 `FileDisplayService` 和 `FileExplorerDisplayService` → `DisplayService`
  - 合并 `FilenameParser` 和 `FileProcessorService` → `FileProcessingService`
  - 合并所有缓存相关服务 → `CacheService`

- **简化服务容器**
  - 废弃当前的 `ServiceContainer` 复杂实现
  - 采用简单的依赖注入模式
  - 减少全局单例模式的使用

- **建立清晰的分层架构**
  ```
  Core          // 核心域
  ├── Models    // 数据模型
  ├── Services  // 核心服务
  ├── Events    // 事件定义
  
  Features      // 功能模块
  ├── Display   // 显示相关功能
  ├── Processing// 文件处理功能
  ├── Links     // 链接处理功能
  
  Infrastructure// 基础设施
  ├── Cache     // 缓存机制
  ├── UI        // UI组件
  ├── Utils     // 工具函数
  ```

### 1.2 插件入口重构（1周）

- **简化 `plugin.ts`**
  - 减少直接服务引用
  - 将初始化逻辑分离到 `Bootstrapper` 类
  - 清理扩展管理代码

- **统一事件管理**
  - 重构 `EventManagerService`
  - 采用发布订阅模式管理插件事件

### 1.3 编辑器扩展简化（1周）

- **简化 CodeMirror 扩展管理**
  - 减少扩展分组和管理复杂度
  - 重构 `EditorLinkDecorator` 为更小的组件
  - 优化链接装饰性能

## 第二阶段：缓存系统优化（3周）

### 2.1 缓存架构重构（1.5周）

- **简化缓存系统**
  - 合并 `FileDisplayCache`、`CacheManager` 等组件
  - 减少缓存策略的数量，保留最有效的实现
  - 简化缓存接口

- **缓存性能优化**
  - 优化缓存键的设计
  - 实现更高效的序列化和反序列化
  - 减少缓存操作开销

### 2.2 缓存同步与持久化（1.5周）

- **改进缓存同步机制**
  - 解决潜在的数据不一致问题
  - 优化缓存更新策略
  - 减少不必要的缓存刷新

- **优化持久化策略**
  - 重构 `PersistentCacheService`
  - 实现增量缓存持久化
  - 提高缓存加载速度

## 第三阶段：功能优化与质量提升（3周）

### 3.1 性能优化（1周）

- **减少 DOM 操作**
  - 优化 `FileExplorerDisplayService` 中的 DOM 操作
  - 使用虚拟 DOM 或批量更新

- **优化正则表达式处理**
  - 重构 `FilenameParser` 中的正则处理逻辑
  - 缓存编译后的正则表达式

- **减少事件处理开销**
  - 优化事件监听器数量
  - 实现事件节流或防抖

### 3.2 错误处理改进（1周）

- **完善错误处理机制**
  - 统一错误处理策略
  - 提供更友好的用户错误提示
  - 实现错误恢复机制

- **改进日志系统**
  - 完善日志分级
  - 实现日志过滤和格式化
  - 添加调试日志开关

### 3.3 代码质量提升（1周）

- **重构长函数**
  - 分解超过50行的函数
  - 提取公共逻辑到工具函数

- **消除代码重复**
  - 提取公共模式
  - 实现代码复用

- **完善类型定义**
  - 消除 `any` 类型使用
  - 增强泛型约束
  - 利用 TypeScript 的高级类型特性

## 优先级与评估指标

### 优先级

1. 架构重构 - 高优先级，是其他改进的基础
2. 缓存系统优化 - 高优先级，直接影响性能
3. 性能优化 - 中高优先级，提升用户体验
4. 错误处理改进 - 中优先级，提升稳定性
5. 代码质量提升 - 中优先级，为长期维护奠定基础
6. 测试覆盖率提升 - 中优先级，保障质量
7. 用户文档改进 - 低优先级，完善用户体验

### 评估指标

- **架构复杂度**：服务数量减少50%以上
- **性能提升**：文件加载与显示速度提升30%以上
- **内存占用**：减少内存峰值使用20%以上
- **代码质量**：消除所有TypeScript警告，无any类型
- **测试覆盖率**：核心功能测试覆盖率达到80%以上
- **用户反馈**：收集用户反馈评分提升

## 风险与缓解策略

### 潜在风险

1. **重构引入新问题**：架构变更可能引入新的bug
   - 缓解：渐进式重构，每个模块重构后进行充分测试

2. **性能退化**：新实现可能导致性能下降
   - 缓解：制定性能基准，确保每次变更不降低性能

3. **兼容性问题**：API变更可能影响现有数据
   - 缓解：实现数据迁移策略，保证向后兼容

4. **开发资源限制**：重构工作量大
   - 缓解：按优先级分阶段实施，先解决关键问题

## 结论

通过这个优化计划，TitleExtractor插件将获得更简洁的架构、更高的性能和更好的可维护性。虽然重构需要投入较多资源，但长期收益显著，能够为用户提供更流畅的体验，也为未来功能扩展奠定坚实基础。
