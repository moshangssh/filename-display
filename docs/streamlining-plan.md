# TitleExtractor 项目精简计划

## 项目概述

TitleExtractor 是一个 Obsidian 插件，主要功能是根据正则表达式提取文件名中的内容来替换文件的显示名称，优化双链接缓存提升显示性能。当前项目结构较为复杂，包含大量服务组件和功能模块，可以通过精简来保留核心功能。

## 核心功能识别

通过分析项目代码，我们识别出以下核心功能：

1. **文件名解析** - 使用正则表达式从文件名中提取显示名称
2. **显示名称缓存** - 缓存提取的显示名称以提高性能
3. **文件资源管理器集成** - 在文件资源管理器中显示提取的标题
4. **Markdown 链接处理** - 处理文档中的链接显示
5. **编辑器链接装饰** - 在编辑器中美化链接显示
6. **用户设置** - 允许用户自定义正则表达式和其他设置

## 精简策略

### 1. 简化服务架构

当前项目使用了复杂的服务容器和依赖注入系统，可以简化为更直接的服务调用：

- 移除 `ServiceContainer` 和 `DependencyResolver`
- 简化服务初始化和依赖管理
- 直接在插件主类中初始化和管理必要服务

### 2. 保留核心服务

只保留以下核心服务：

- `FilenameParser` - 文件名解析
- `FileDisplayCache` - 显示名称缓存
- `FileDisplayService` - 文件显示服务
- `FileExplorerDisplayService` - 文件资源管理器显示服务
- `MarkdownLinkService` - Markdown链接处理
- `EditorLinkDecorator` - 编辑器链接装饰（可选）

### 3. 简化缓存机制

精简当前复杂的多层缓存系统：

- 合并多个缓存服务为单一缓存服务
- 移除过于复杂的缓存策略，使用简单的LRU缓存
- 减少缓存相关的配置选项

### 4. 移除非必要功能

以下功能可以考虑移除：

- 复杂的性能监控系统
- 多层错误处理机制
- 事件总线和事件管理
- 批处理服务
- DOM观察服务（除非必要）

### 5. 简化设置界面

- 减少设置选项，只保留关键配置项
- 移除高级/调试相关设置

## 实施计划

### 阶段一：核心功能提取

1. 创建新的精简版插件主类
2. 实现基本的文件名解析和显示功能
3. 创建简化的缓存服务

### 阶段二：核心UI集成

1. 实现文件资源管理器显示服务
2. 实现基本的链接处理功能
3. 开发简化的设置界面

### 阶段三：测试与优化

1. 测试核心功能
2. 优化性能
3. 添加必要的错误处理

## 文件结构对比

### 当前结构
```
src/
  ├── core/        - 复杂的依赖注入和服务管理
  ├── services/    - 大量服务组件
  ├── utils/       - 工具函数
  ├── settings/    - 设置相关
  ├── extensions/  - 编辑器扩展
  ├── plugin.ts    - 主插件类(925行)
  └── ...
```

### 精简后结构
```
src/
  ├── core/              - 精简的核心功能
  │   ├── Parser.ts      - 文件名解析
  │   └── Cache.ts       - 简单缓存
  ├── display/           - 显示相关
  │   ├── FileExplorer.ts - 文件资源管理器集成
  │   └── LinkDisplay.ts  - 链接显示
  ├── settings/          - 简化的设置
  ├── utils/             - 必要的工具函数
  └── plugin.ts          - 精简后的主插件类
```

## 总结

通过精简项目，我们可以移除不必要的复杂性，专注于核心功能的实现。这将使代码更易于维护，同时保持插件的主要功能和性能优势。精简后的插件将仍然提供文件名提取和显示的核心功能，但具有更简单的架构和更少的代码量。

建议在实施精简计划前，先创建完整的项目备份，并在测试环境中验证精简后的功能是否符合预期。🔍✂️
