# TitleExtractor 循环依赖解决方案

## 1. 循环依赖问题分析

在当前的 TitleExtractor 插件架构中，存在明显的循环依赖问题，尤其是在以下组件之间：

1. **FileProcessorService 和 FileDisplayCache**
   - FileProcessorService 需要 FileDisplayCache 来检查和存储处理结果
   - FileDisplayCache 需要 FileProcessorService 来处理缓存未命中的情况

2. **Plugin 和各服务组件**
   - 插件实例持有所有服务的引用
   - 服务需要插件实例来访问设置和应用功能

3. **事件管理和服务层之间**
   - EventManagerService 需要调用多个服务的方法
   - 这些服务可能同时也需要 EventManagerService

这些循环依赖导致了代码难以理解、测试和维护，也增加了初始化的复杂性。

## 2. 解决策略

### 2.1 采用依赖倒置原则 (DIP)

依赖倒置原则是解决循环依赖的核心策略，通过引入抽象接口和依赖注入来打破直接依赖关系。

#### 具体实现步骤：

1. **定义接口**

为所有参与循环依赖的服务定义清晰的接口：

```typescript
// 文件: src/services/interfaces/IFileProcessorService.ts
export interface IFileProcessorService {
    processFile(file: TFile): Promise<FileDisplayResult>;
    // 其他方法...
}

// 文件: src/services/interfaces/IFileDisplayCache.ts
export interface IFileDisplayCache {
    getDisplayName(file: TFile): string | null;
    setDisplayName(file: TFile, displayName: string): void;
    // 其他方法...
}
```

2. **使用工厂模式和延迟绑定**

```typescript
// 文件: src/services/factories/ServiceFactory.ts
export class ServiceFactory {
    private static instance: ServiceFactory;
    private services: Map<string, any> = new Map();
    private serviceFactories: Map<string, () => any> = new Map();
    
    static getInstance(): ServiceFactory {
        if (!ServiceFactory.instance) {
            ServiceFactory.instance = new ServiceFactory();
        }
        return ServiceFactory.instance;
    }
    
    register<T>(serviceId: string, factory: () => T): void {
        this.serviceFactories.set(serviceId, factory);
    }
    
    get<T>(serviceId: string): T {
        if (this.services.has(serviceId)) {
            return this.services.get(serviceId);
        }
        
        const factory = this.serviceFactories.get(serviceId);
        if (!factory) {
            throw new Error(`Service not registered: ${serviceId}`);
        }
        
        const service = factory();
        this.services.set(serviceId, service);
        return service;
    }
}
```

### 2.2 使用事件系统解耦

使用事件发布/订阅模式，代替直接方法调用，降低组件间耦合度。

```typescript
// 文件: src/services/EventBusService.ts
export class EventBusService {
    private static instance: EventBusService;
    private listeners: Map<string, Function[]> = new Map();
    
    static getInstance(): EventBusService {
        if (!EventBusService.instance) {
            EventBusService.instance = new EventBusService();
        }
        return EventBusService.instance;
    }
    
    on(event: string, callback: Function): void {
        if (!this.listeners.has(event)) {
            this.listeners.set(event, []);
        }
        this.listeners.get(event)?.push(callback);
    }
    
    emit(event: string, ...args: any[]): void {
        const callbacks = this.listeners.get(event) || [];
        callbacks.forEach(callback => callback(...args));
    }
}
```

### 2.3 重构 ServiceContainer

优化 ServiceContainer，支持延迟初始化和解决循环依赖：

```typescript
// 文件: src/core/ServiceContainer.ts
export class ServiceContainer {
    private static instance: ServiceContainer;
    private services: Map<string, any> = new Map();
    private factories: Map<string, () => any> = new Map();
    private pendingPromises: Map<string, Promise<any>> = new Map();
    
    static getInstance(): ServiceContainer {
        if (!ServiceContainer.instance) {
            ServiceContainer.instance = new ServiceContainer();
        }
        return ServiceContainer.instance;
    }
    
    register<T>(serviceId: string, instance: T): void {
        this.services.set(serviceId, instance);
    }
    
    registerFactory<T>(serviceId: string, factory: () => T): void {
        this.factories.set(serviceId, factory);
    }
    
    async get<T>(serviceId: string): Promise<T> {
        // 检查是否已初始化
        if (this.services.has(serviceId)) {
            return this.services.get(serviceId);
        }
        
        // 检查是否有pending的初始化
        if (this.pendingPromises.has(serviceId)) {
            return this.pendingPromises.get(serviceId);
        }
        
        // 检查是否有工厂方法
        const factory = this.factories.get(serviceId);
        if (!factory) {
            throw new Error(`Service not registered: ${serviceId}`);
        }
        
        // 创建并缓存初始化Promise
        const promise = Promise.resolve().then(() => {
            const instance = factory();
            this.services.set(serviceId, instance);
            this.pendingPromises.delete(serviceId);
            return instance;
        });
        
        this.pendingPromises.set(serviceId, promise);
        return promise;
    }
    
    // 同步获取（仅当服务已初始化时使用）
    getSync<T>(serviceId: string): T | null {
        return this.services.get(serviceId) || null;
    }
}
```

## 3. 重构服务的具体实现

### 3.1 FileProcessorService 的重构

```typescript
// 文件: src/services/FileProcessorService.ts
export class FileProcessorService implements IFileProcessorService {
    private fileDisplayCache: IFileDisplayCache | null = null;
    private serviceContainer: ServiceContainer;
    
    constructor(
        private plugin: Plugin,
        private filenameParser: FilenameParser,
        private loggerService: LoggerService
    ) {
        this.serviceContainer = ServiceContainer.getInstance();
    }
    
    // 使用延迟加载获取缓存服务
    private async getCache(): Promise<IFileDisplayCache> {
        if (!this.fileDisplayCache) {
            this.fileDisplayCache = await this.serviceContainer.get<IFileDisplayCache>('fileDisplayCache');
        }
        return this.fileDisplayCache;
    }
    
    async processFile(file: TFile): Promise<FileDisplayResult> {
        // 实现处理逻辑
        const result = await this.filenameParser.parse(file);
        
        // 使用异步方法获取缓存
        const cache = await this.getCache();
        if (result.success) {
            cache.setDisplayName(file, result.displayName);
        }
        
        return result;
    }
}
```

### 3.2 FileDisplayCache 的重构

```typescript
// 文件: src/services/cache/FileDisplayCache.ts
export class FileDisplayCache implements IFileDisplayCache {
    private cache: Map<string, string> = new Map();
    private serviceContainer: ServiceContainer;
    
    constructor(
        private plugin: Plugin,
        private loggerService: LoggerService
    ) {
        this.serviceContainer = ServiceContainer.getInstance();
    }
    
    getDisplayName(file: TFile): string | null {
        const path = file.path;
        if (this.cache.has(path)) {
            return this.cache.get(path) || null;
        }
        
        // 缓存未命中，触发事件而不是直接调用处理服务
        const eventBus = this.serviceContainer.getSync<EventBusService>('eventBus');
        if (eventBus) {
            eventBus.emit('cache:miss', file);
        }
        
        return null;
    }
    
    setDisplayName(file: TFile, displayName: string): void {
        this.cache.set(file.path, displayName);
    }
}
```

### 3.3 注册服务和处理循环依赖

```typescript
// 文件: src/plugin.ts (部分代码)
private setupServices(): void {
    const container = ServiceContainer.getInstance();
    const eventBus = new EventBusService();
    
    // 首先注册事件总线
    container.register('eventBus', eventBus);
    
    // 注册基础服务
    container.register('loggerService', new LoggerService());
    container.register('timerService', new TimerService(this));
    
    // 使用工厂方法注册可能参与循环依赖的服务
    container.registerFactory('filenameParser', () => new FilenameParser(this, container.getSync('loggerService')));
    
    container.registerFactory('fileProcessorService', () => 
        new FileProcessorService(
            this, 
            container.getSync('filenameParser'), 
            container.getSync('loggerService')
        )
    );
    
    container.registerFactory('fileDisplayCache', () => 
        new FileDisplayCache(
            this, 
            container.getSync('loggerService')
        )
    );
    
    // 设置事件监听以解决缓存未命中情况
    eventBus.on('cache:miss', async (file: TFile) => {
        const processor = await container.get<IFileProcessorService>('fileProcessorService');
        await processor.processFile(file);
    });
}
```

## 4. 依赖图分析与优化

通过上述重构，TitleExtractor 插件的依赖关系将从原来的:

```
FileProcessorService <---> FileDisplayCache
Plugin <---> Services
EventManager <---> Services
```

优化为单向依赖的结构:

```
Plugin --> IServices
Services --> Events
Services --> ServiceContainer
```

这种结构更加清晰，避免了循环引用，同时提高了代码的可测试性。

## 5. 测试策略

1. **模拟依赖**：使用 Jest 的 mock 功能模拟服务接口
2. **独立测试**：每个服务组件可以独立测试
3. **集成测试**：通过 ServiceContainer 测试服务间的协作

## 6. 迁移策略

为了平稳迁移到新架构，可以采用以下步骤：

1. **定义所有必要的接口**
2. **实现新的 ServiceContainer 和工厂**
3. **逐个重构服务**，优先重构底层基础设施
4. **更新插件主类**，使用新的服务注册方法
5. **全面测试**，确保功能正常

通过这种渐进式的重构方法，可以在保持插件功能稳定的同时，逐步消除循环依赖，提高代码质量和可维护性。🔄🛠️
